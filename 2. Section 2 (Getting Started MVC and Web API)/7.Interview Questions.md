# ASP.NET Core Interview Notes

---

# 1. What is Kestrel and what are advantages of Kestrel in ASP.NET Core?

ASP.NET Core application uses **Kestrel by default**.

Kestrel is an **event-driven, I/O-based, open-source, cross-platform, and asynchronous server** which hosts .NET applications.

It is provided as a **default server for .NET Core**; therefore, it is compatible with all the platforms and their versions which .NET Core supports.

It is a **listening server with a command-line interface**.

It can be used with **reverse proxy servers such as IIS, Nginx etc.**

## Features of Kestrel

- Lightweight and fast  
- Cross-platform and supports all versions of .NET Core  
- Supports HTTP & HTTPS  
- Easy configuration  
- Multiple apps on the same port is not supported  
- Windows authentication is not supported

# 2. What is the difference between IIS and Kestrel? Why do we need two web servers?

The main difference between IIS and Kestrel is that **Kestrel is a cross-platform server**.

- Kestrel runs on **Windows, Linux, and Mac**
- IIS runs **only on Windows**

Another important difference:

- **Kestrel is fully open-source**
- **IIS is closed-source and developed and maintained by Microsoft**

IIS is **very old software** and comes with a considerable **legacy and bloat**.

With Kestrel, Microsoft focused on **high performance** and built it **from scratch**, allowing them to ignore legacy compatibility issues.

However, Kestrel **does not provide all the rich features** of a full web server like:

- IIS
- Nginx
- Apache

Therefore, we usually use:

```

Reverse Proxy Server (IIS / Nginx / Apache)
↓
Kestrel
↓
ASP.NET Core Application

```

# 3. What is the purpose of launchSettings.json in ASP.NET Core?

The **launchSettings.json** file stores **configuration information used to start the ASP.NET Core application in Visual Studio**.

It mainly contains:

- Runtime profiles
- Application URLs
- Environment settings

Important points:

- Used **only during development**
- Contains settings required to **run the application locally**
- Used **only by Visual Studio**

You **do not need launchSettings.json when publishing the application to production**.

# 4. What is Generic Host or HostBuilder in .NET Core?

The **.NET Generic Host (HostBuilder)** helps manage the following tasks:

- Dependency Injection
- Service lifetime management
- Configuration
- Logging

Previously, **Web Host** was used for web applications in early .NET Core versions.

Later:

- **Web Host was deprecated**
- **Generic Host was introduced**

Generic Host supports multiple application types:

- Web applications
- Console applications
- Windows services
- Linux services

# 5. What is the purpose of the .csproj file?

The **.csproj file** is one of the most important files in a .NET project.

It tells **.NET how to build (compile) the project**.

The .csproj file contains:

- Target .NET version
- Package dependencies
- Compilation settings
- Project type

It also stores information needed by **.NET tooling to build the project**, including:

- Project type (Web, Console, Desktop)
- Target platform
- Dependencies on other projects
- Third-party libraries

## Example .csproj File

```csharp
<Project Sdk="Microsoft.NET.Sdk.Web">
<PropertyGroup>
  <TargetFramework>net6.0</TargetFramework>
</PropertyGroup>

<ItemGroup>
  <PackageReference Include="PackageName" Version="1.0.0.0" />
</ItemGroup>
</Project>
```

# 6. What is IIS?

IIS stands for **Internet Information Services**.

It is a **powerful web server developed by Microsoft**.

IIS can act as a:

* Web server
* Load balancer
* Reverse proxy

## Load Balancing

IIS can distribute incoming HTTP requests to **multiple application servers**, improving:

* Reliability
* Scalability

## Reverse Proxy

IIS can:

1. Accept client request
2. Forward it to application server (like Kestrel)
3. Return the response to the client

Reverse proxy improves:

* Security
* Reliability
* Performance

### Limitation of IIS

* Runs **only on Windows**

However, IIS is **highly configurable** and can be customized according to application needs.

# 7. What is the "Startup" class in ASP.NET Core (prior to ASP.NET Core 6)?

The **Startup class** is the **entry point of an ASP.NET Core application** (ASP.NET Core 5 and earlier).

It contains the code required to **bootstrap the application**.

The Startup class has two important methods:

## Configure()

Used to **add middleware to the application request pipeline**.

## ConfigureServices()

Used to **register services into the IoC container**.

### ASP.NET Core 6 Change

In **ASP.NET Core 6 (.NET 6)**:

* `Startup.cs` and `Program.cs` were **merged into a single Program.cs file**

Now the **Program.cs file handles**:

* Registering middleware
* Adding services to IoC container
* Application configuration
* Logging
* Authentication
* Database context configuration

# 8. What does WebApplication.CreateBuilder() do?

`WebApplication.CreateBuilder()` performs several setup tasks automatically.

It does the following:

* Configures **Kestrel as the web server**
* Uses the **current project directory as the root directory**
* Reads configuration from:

  * `appsettings.json`
  * `appsettings.{environment}.json`
* Enables **Local User Secrets** for development environment
* Reads **environment variables**
* Supports **command-line arguments**
* Configures **logging system**

  * Console logging
  * Debug logging
* Enables **integration with IIS**
* Configures the **default service provider**
